# VLUR CAPTCHA 앙상블 모델 개요

VLUR CAPTCHA는 사용자가 문제에 제출한 "정답 여부"와, 그 답을 만들어내기까지의 "드래그 동작 자체"를 함께 분석해 사람과 봇을 구분하는 행동 기반 CAPTCHA입니다. 이미지를 정확히 골랐는지뿐 아니라 마우스·터치·펜으로 이미지를 드래그한 궤적(경로, 속도, 가속도, 회전 패턴 등)을 딥러닝 모델로 분석해, 단순 스크립트나 자동화 도구가 흉내 내기 어려운 사람 고유의 움직임 특성을 판별 기준으로 삼습니다.

핵심 판별 엔진은 서로 다른 방식으로 학습된 두 개의 딥러닝 모델 — 1D CNN과 양방향 LSTM(BiLSTM) — 을 결합한 앙상블입니다.

# 판정 절차

한 번의 인증 요청은 크게 두 가지 신호를 결합해 최종 결과를 냅니다.

첫째는 정답 판정입니다. 제출한 보기가 문제와 실제로 일치하는지 서버가 확인합니다.

둘째는 행동 판정(앙상블 모델)입니다. 드래그 궤적을 CNN·BiLSTM 앙상블에 입력해 사람다운 움직임인지 판별하며, 판정은 세 단계로 나뉩니다. 정상(verified)은 사람의 움직임으로 판단한 경우, 판정 보류(ambiguous)는 애매하여 재검증이 필요한 경계 상태, 봇 의심(blocked)은 봇의 움직임으로 판단한 경우입니다.

정답이 맞아도 행동 판정이 "봇 의심"이면 인증은 최종 실패로 처리됩니다. 반대로 행동 판정이 정상이어도 정답이 틀리면 당연히 실패합니다. 즉 두 신호 중 하나라도 기준을 통과하지 못하면 인증이 성립하지 않는 구조입니다.

여기에 더해, 문제가 표시된 시점부터 응답이 완료되기까지의 시간이 물리적으로 사람이 낼 수 없는 수준(약 0.2초 이하)이면, 앙상블 모델의 점수와 무관하게 곧바로 봇으로 처리하는 별도의 안전장치도 함께 작동합니다.

# 왜 모델을 두 개 쓰는가

하나의 모델만으로 판별하면 그 모델이 놓치는 패턴에 취약해집니다. VLUR CAPTCHA는 서로 다른 관점으로 궤적을 보는 두 모델을 독립적으로 학습시킨 뒤, 한쪽이라도 "봇"이라고 판단하면 최종적으로 봇 처리하는 방식(OR 결합)을 기본값으로 채택했습니다.

내부 검증 결과, 두 모델 점수를 회귀식으로 합치는 방식보다 이 방식이 실제 회피 시도에 대한 방어력이 더 높은 것으로 확인되어 기본 판정 방식으로 확정했습니다.

# 모델 A — 1D CNN (Ultra_CNN_v2)

드래그 궤적을 시간 축을 따라 흐르는 1차원 신호로 보고 분석하는 합성곱 신경망입니다.

위치·속도·가속도·저크(가속도 변화율)·회전각 등으로 구성된 시계열을 3단계의 합성곱 블록(Conv1D + BatchNorm + ReLU, 앞 두 블록은 MaxPooling 포함)에 통과시켜 시간 축 전체의 지역적 패턴을 추출합니다.

이와 별도로, 궤적 전체를 요약하는 기하학적 통계치(직선성, 속도 변동성, 곡률, 방향 전환 횟수 등)를 작은 완전연결 계층(scalar branch)에 통과시킵니다.

두 경로에서 나온 특징을 합친 뒤 완전연결 계층(head)을 거쳐 "봇일 확률"을 하나의 값으로 출력합니다.

CNN은 궤적의 형태와 국소적인 움직임 패턴(속도·가속도·저크의 순간적인 변화, 방향 전환 지점 등)을 포착하는 데 강합니다. 정해진 경로를 그대로 재생하거나 좌표를 단순하게 흉내 내는 스크립트·매크로형 자동화 트래픽을 잘 잡아냅니다. 다만 궤적 전체의 통계적인 형태만으로는, 사람의 속도 변화 패턴을 정교하게 흉내 내도록 통계적으로 합성된 궤적에 대해 상대적으로 판별력이 떨어질 수 있습니다 — 이런 유형은 BiLSTM이 보완합니다.

학습 시에는 마우스·터치·펜 포인터 종류별로 균형 잡힌 데이터를 사용하고, 라벨 스무딩·도메인 적대적 학습·hard negative 샘플 추가 학습 등 일반화 성능을 높이기 위한 여러 기법을 함께 적용했습니다. 이를 통해 특정 포인터 유형에 치우치지 않고 마우스·터치·펜 각각에 대해 안정적으로 판별하도록 조정되어 있습니다. 판정 기준값(threshold)은 목표 오탐률을 만족하도록 검증 데이터에서 포인터 종류별로 따로 보정하는데, 정확한 기준값 자체는 보안상 비공개입니다. 모델 체크포인트는 새로운 학습 기법이 검증될 때마다 갱신되며, 배포 버전은 CNN 단독이 아니라 BiLSTM과 결합된 앙상블 체크포인트입니다.

# 모델 B — 2계층 양방향 LSTM (BiLSTM)

같은 궤적을 순차적인 시계열 자체로 보고 앞뒤 문맥을 함께 참고해 분석하는 순환 신경망입니다.

2개 층으로 쌓인 양방향 LSTM(은닉 상태 크기 128)에 궤적 시계열을 통과시켜, 순방향·역방향 문맥을 모두 반영한 요약 표현을 얻습니다.

여기에 궤적의 요약 통계치(기하학적 특성 + 곡선 근사 기반 특성)를 추가로 붙여 작은 완전연결 계층(head)에 통과시켜 "봇일 확률"을 출력합니다.

별도의 어텐션 구조 없이, LSTM의 최종 은닉 상태를 그대로 요약 표현으로 사용하는 비교적 단순하고 가벼운 구조입니다.

BiLSTM은 궤적을 시간 순서대로 읽으며 속도 변화의 문맥적인 흐름을 함께 분석합니다. 이 덕분에 통계적인 운동학 모델로 사람의 움직임을 흉내 내려는, 정교하게 다듬어진 합성 궤적 유형에 대해 CNN보다 더 강한 탐지력을 보이는 것으로 내부 검증에서 확인되었습니다. CNN과 BiLSTM이 서로 다른 유형의 자동화 공격에 강점을 갖기 때문에, 앙상블로 결합하면 한 모델의 사각지대를 다른 모델이 메워주는 효과가 있습니다.

# 입력 데이터 전처리 (정본화, Canonicalization)

두 모델 모두 원본 좌표(x, y, 시간)를 그대로 쓰지 않고 공통 전처리를 거친 뒤 입력받습니다.

리샘플링은 샘플링 간격이 제각각인 원본 좌표를 일정한 개수의 지점으로 균일하게 재구성합니다.

원점 정렬 및 거리 정규화는 드래그 시작 지점을 기준으로 좌표를 이동시키고, 문제에서 정의된 이동 거리 기준으로 스케일을 맞춥니다.

회전 정렬은 전체 이동 방향을 기준 축에 맞춰 회전시켜, 같은 모양의 움직임이면 화면상 어느 방향으로 드래그했든 동일하게 인식되도록 합니다.

스케일 정규화는 이동 크기 차이에 따른 영향을 제거해 "움직임의 형태" 자체에 집중할 수 있게 합니다.

이 과정을 거치면 화면 해상도, 문제 배치, 사용자의 절대적인 이동 거리·속도 차이와 무관하게 두 모델이 "움직임의 패턴"만을 비교할 수 있습니다.

# 공개 성능 지표

VLUR CAPTCHA 사이트에 실측 기준으로 공개하고 있는 지표는 세 가지입니다.

분류 정확도는 97.5%로, 자체 데이터셋 기반 검증 정확도입니다.

오탐률은 0.3% 이하로, 실제 사람을 봇으로 잘못 판정하는 비율입니다.

검증 처리량은 초당 25~40건이며, 궤적 분석을 포함한 레코드 단위 처리 건수입니다.

이 수치들은 사람 트래픽과, 사람 행동을 흉내 내려는 다양한 자동화 트래픽(스크립트 기반, 생성모델 기반 등)을 함께 검증해 얻은 결과이며, 지속적으로 재검증하고 있습니다.

# 추가 안전장치

초고속 응답 자동 차단은 문제 노출부터 응답 완료까지 걸린 시간이 사람이 물리적으로 낼 수 없는 수준으로 짧으면, 앙상블 모델의 판정 결과와 무관하게 즉시 봇으로 처리하는 장치입니다.

판정 보류(ambiguous) 상태는 모델이 확신을 갖고 판단하기 어려운 경계 사례를 곧바로 통과시키거나 차단하지 않고 보류해, 재시도를 요구하는 방식으로 처리합니다.

# 지속적인 개선

공격 기법(자동화 스크립트, 생성모델 기반 궤적 합성 등)은 계속 진화하기 때문에, 완벽하게 고정된 방어선이란 존재하지 않습니다. VLUR CAPTCHA 팀은 새로운 유형의 자동화 트래픽 샘플을 주기적으로 확보해 모델을 재검증·재학습하고, 앙상블 결합 방식과 보조 판별 로직을 지속적으로 보강하는 방식으로 대응하고 있습니다.

# 자주 묻는 질문

이미지만 맞히면 통과되나요? 아니요. 정답 여부와 별개로 드래그 동작 자체를 분석하는 행동 기반 판정이 함께 적용됩니다. 정답을 맞혀도 동작이 봇처럼 보이면 인증에 실패할 수 있습니다.

어떤 AI 모델을 쓰나요? 1D CNN과 양방향 LSTM(BiLSTM), 두 개의 독립적인 딥러닝 모델을 함께 사용하는 앙상블 구조입니다.

두 모델의 결과가 다르면 어떻게 되나요? 둘 중 하나라도 봇이라고 판단하면 최종적으로 봇으로 처리합니다(OR 결합). 어느 한쪽이 놓친 패턴을 다른 모델이 잡아내도록 설계한 것입니다.

CNN과 BiLSTM은 각각 어떤 기준으로 사람/봇을 나누나요? 두 모델 모두 궤적을 분석해 "봇일 확률"을 산출합니다. CNN은 궤적의 시계열 패턴(속도·가속도·회전각 등)과 궤적 전체의 기하학적 통계치를 함께 보고, BiLSTM은 같은 궤적을 양방향 문맥으로 읽습니다. 두 모델 모두 포인터 종류(마우스/터치/펜)별로 다른 기준값(threshold)을 적용해 확률을 사람/봇으로 나누는데, 정확한 기준값 자체는 보안상 공개하지 않습니다. 최종 판정은 이 두 결과를 OR 결합(하나라도 봇이면 봇)으로 합쳐서 냅니다.

CNN은 어떤 기준으로 봇을 차단하나요? 드래그 궤적의 형태와 국소적인 움직임 패턴(속도·가속도·저크·방향 전환)을 분석해 "봇일 확률"을 산출하고, 정해진 값을 넘으면 봇으로 판정합니다. 스크립트·매크로처럼 경로를 그대로 재생하는 자동화 트래픽 탐지에 강합니다.

BiLSTM은 어떤 기준으로 봇을 차단하나요? 궤적을 시간 순서대로 읽어 속도 변화의 문맥적 흐름을 분석해 "봇일 확률"을 산출하고, 정해진 값을 넘으면 봇으로 판정합니다. 사람의 움직임을 통계적으로 정교하게 흉내 낸 합성 궤적 탐지에 CNN보다 강점이 있습니다.

다른 일반적인 CAPTCHA나 단일 CNN·단일 BiLSTM 모델과는 뭐가 다른가요? 왜곡된 글자를 읽히거나 이미지를 한 번 선택하는 것만으로 통과되는 기존 CAPTCHA 방식은 정답 여부만 확인할 뿐 행동 검증이 없어 자동화 도구나 매크로에 취약합니다. VLUR CAPTCHA는 정답 여부에 더해 드래그 궤적 자체를 분석합니다. 또한 CNN이나 BiLSTM 중 하나만 단독으로 쓰는 방식과도 다릅니다 — 단일 모델은 그 모델이 놓치는 패턴에 그대로 뚫리지만, VLUR CAPTCHA는 서로 다른 관점으로 궤적을 보는 두 모델을 독립적으로 학습시켜 하나라도 봇이라 판단하면 최종적으로 차단하는 OR 결합 방식을 씁니다. 내부 검증에서 이 방식이 단일 모델이나 두 모델 점수를 합산하는 방식보다 실제 회피 시도에 대한 방어력이 더 높은 것으로 확인되었습니다.

정확도는 어느 정도인가요? 자체 데이터셋 기준 분류 정확도 97.5%, 실제 사람을 봇으로 잘못 판정하는 오탐률은 0.3% 이하입니다.

처리 속도는 어느 정도인가요? 레코드 단위로 초당 25~40건을 처리합니다(궤적 분석 포함 기준).
